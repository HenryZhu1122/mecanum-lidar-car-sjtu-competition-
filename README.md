# RPLidar Mecanum Car

基于 ESP32、RPLidar 激光雷达与麦克纳姆轮底盘的智能小车控制项目。

本项目最初目标是实现小车的基础直行、纠偏和前方避障转向。经过多轮实车调试后，当前版本已经从基础可运行版本升级为面向 8 字赛道的路径控制版本。小车能够利用激光雷达识别赛道结构，在完成一个 8 字路线后继续掉头，并按相反方向再完成一个 8 字路线。

当前版本为：

```text
v0.20 - 8 字赛道往返控制版本
```

---

## 项目简介

本项目使用 RPLidar 获取小车周围 360° 距离信息，并通过麦克纳姆轮底盘实现直行、横移、原地转向和角度修正。

当前控制逻辑并不依赖摄像头视觉识别，而是主要通过雷达距离数据判断赛道结构，包括：

* 前方是否到达转弯点
* 左右侧是否存在开口
* 是否处于 8 字中间路口
* 是否需要延迟转弯
* 是否需要在正常行走过程中修正车头角度

相比基础版本，v0.20 的重点不再是“能不能走”，而是“能不能按照 8 字赛道稳定走完整条路线”。

## 电机通道标定

经过实车测试，`MecanumDriver` 四路输出与实际轮子的对应关系如下：

| 输出通道  | 实际轮子 | 正值方向 |
| ----- | ---- | ---- |
| 第 1 路 | 左后轮  | 后转   |
| 第 2 路 | 右后轮  | 后转   |
| 第 3 路 | 右前轮  | 前转   |
| 第 4 路 | 左前轮  | 前转   |

由于后轮方向与前轮方向不同，程序在 `driveFixed()` 中进行了方向修正，使上层控制逻辑可以统一按照：

```text
fl / fr / bl / br 为正值时，对应轮子向前转
```

来理解轮速。

当前已经验证以下基础动作可以正常执行：

* 直行
* 后退
* 左转
* 右转
* 左平移
* 右平移

## 麦克纳姆轮运动控制

程序通过：

```cpp
setSpeed(speedX, speedY, angularW);
```

统一控制小车运动。

三个参数含义如下：

| 参数         | 含义            |
| ---------- | ------------- |
| `speedX`   | 前进 / 后退速度     |
| `speedY`   | 左右平移速度        |
| `angularW` | 原地转向 / 角度修正速度 |

在底层，程序会将 `speedX`、`speedY`、`angularW` 合成为四个轮子的目标速度，再通过 `driveFixed()` 进行方向映射和限幅。

## 雷达角度定义

根据当前雷达安装方向，程序使用以下角度定义：

```cpp
const int F_ANGLE = 180;
const int L_ANGLE = 110;
const int R_ANGLE = 250;
```

| 方向   | 雷达角度 |
| ---- | ---- |
| 前方   | 180° |
| 左侧前方 | 110° |
| 右侧前方 | 250° |

程序使用：

```cpp
float lidarDistances[360] = {0};
```

保存 0° 到 359° 的雷达距离数据。每次读取到雷达扫描点后，根据该点角度更新对应数组位置。

为了降低单点数据波动，程序通过：

```cpp
getAvgDistance(centerAngle, range)
```

获取某个中心角附近一段范围内的平均距离。

## 核心状态机

当前版本包含以下运行状态：

```cpp
#define MODE_RUN               0
#define MODE_TURN_LEFT         1
#define MODE_TURN_RIGHT        2
#define MODE_POST_TURN         3
#define MODE_EIGHT_DELAY_TURN  4
```

### MODE_RUN

正常运行状态。

在该状态下，小车会持续读取前方、左侧、右侧雷达距离，并依次执行：

1. 雷达数据有效性检查
2. 8 字路口判断
3. 普通 L 弯判断
4. 横向纠偏
5. 角度微修正
6. 正常前进

### MODE_TURN_LEFT / MODE_TURN_RIGHT

固定时间转弯状态。

当前转弯仍使用定时控制：

```cpp
const unsigned long TURN_DURATION = 875;
```

转弯完成后进入 `MODE_POST_TURN`。

### MODE_POST_TURN

转弯后强制直行状态。

该状态用于避免刚转完后雷达数据不稳定，导致小车马上再次误判路口。

```cpp
const unsigned long POST_TURN_RUN = 500;
```

转后直行结束后，程序会短暂锁定绕 8 判断，再回到 `MODE_RUN`。

### MODE_EIGHT_DELAY_TURN

8 字单侧开口延迟转弯状态。

当小车识别到“前方开阔，左侧或右侧突然开阔”的 T 型结构时，不会立刻转弯，而是先继续直行一小段时间：

```cpp
const unsigned long EIGHT_PRE_TURN_RUN = 700;
```

这样可以避免刚看到开口就过早转弯，使小车更接近正确入弯位置。

## 8 字路线控制逻辑

v0.20 的核心升级是加入了 8 字路线控制。

程序将 8 字赛道中的关键路口分为两类。

---

### 类型 1：中心记忆路口

判断条件：

```text
前方距离较近
左侧开阔
右侧开阔
```

也就是小车来到 8 字中心区域时，前方不能继续直行，但左右两侧都存在可通行方向。此时不能简单按照“哪边更空”来转向，否则路线会不稳定。

因此程序使用记忆表控制转向顺序：

```cpp
const int centerRoute[CENTER_ROUTE_COUNT] = {
  EIGHT_LEFT,
  EIGHT_RIGHT,
  EIGHT_LEFT,
  EIGHT_RIGHT,
  EIGHT_LEFT,
  EIGHT_RIGHT,
  EIGHT_LEFT,
  EIGHT_RIGHT
};
```

当前逻辑为：

```text
第一次中心路口：左转
第二次中心路口：右转
第三次中心路口：左转
第四次中心路口：右转
……
```

通过这种方式，小车可以按照预设路线完成 8 字路径，并继续执行反向绕行。

---

### 类型 2：单侧突然开口路口

判断条件：

```text
前方开阔
左侧或右侧突然开阔
另一侧未开阔
```

这种情况通常对应 8 字赛道中的 T 型开口。程序会判断是哪一侧突然开阔，然后向开阔侧转弯。

为了避免过早转弯，程序没有立即转向，而是先进入 `MODE_EIGHT_DELAY_TURN`，继续直行一段时间后再转弯。

---

## 绕 8 锁定机制

由于雷达数据连续更新，小车经过同一个路口时可能在短时间内多次满足判断条件。

为避免同一路口重复触发，程序加入了绕 8 锁定机制：

```cpp
bool eightLocked = false;
unsigned long eightLockTime = 0;
const unsigned long EIGHT_LOCK_TIME = 700;
```

当识别到绕 8 路口后，程序会短暂锁定判断逻辑。在锁定时间内，即使雷达仍然检测到开口，也不会重复触发新的转弯。

转弯结束并完成 `POST_TURN_RUN` 后，程序也会再次短暂锁定绕 8 判断，避免转完后又被同一个路口二次触发。

## 正常行走角度修正

v0.20 在普通直行基础上加入了角度微修正。

程序会分别读取：

```cpp
80° ~ 90°
90° ~ 100°
```

两个角度区间内的平均距离，并计算差值：

```cpp
diff = avg(80°~90°) - avg(90°~100°)
```

再将该差值转换为 `angularW`，叠加到正常行走控制中：

```cpp
setSpeed(BASE_SPEED, lateralSpeed, angularCorrect);
```

这样小车在正常行走时不仅能左右平移纠偏，还能对车头角度进行微调，减少转弯后斜着走的问题。

当前角度修正参数为：

```cpp
const float ANGLE_FIX_KP = 0.7;
const float ANGLE_FIX_MAX = 20.0;
const float ANGLE_FIX_DEADZONE = 0.0;
const float ANGLE_FIX_SIGN = 1.0;
```

## 普通 L 弯判断

除了 8 字路线控制外，程序仍保留了基础的普通 L 型弯道判断。

当小车前方距离小于阈值，且左右至少有一侧可通行时，程序会根据左右距离选择转向方向。

当前普通 L 弯判断加入了额外限制：

```cpp
(left <= 500 || right <= 500)
```

用于减少 8 字中心开阔区域被普通 L 弯逻辑误判的概率。

---

## 雷达异常保护

为了避免雷达异常导致小车失控，程序加入了以下保护：

* 当前、左、右三个方向均无有效数据时，小车停车保护。
* 雷达偶发读取失败时不立即重启。
* 长时间没有有效雷达点时，自动重新启动雷达扫描。
* 控制逻辑每 50ms 执行一次，不依赖单次扫描周期触发。

## 已知问题

* 当前转弯仍主要依赖固定时间控制，尚未加入陀螺仪、编码器或闭环角度控制。
* 8 字判断依赖雷达阈值，赛道宽度、墙面材质、车速变化可能影响识别效果。
* 角度修正使用比例控制，尚未加入完整 PID。
* 当前版本未加入卡死处理逻辑，优先保证主路线稳定性。
* 参数与当前实车、当前场地强相关，换场地后需要重新微调。
